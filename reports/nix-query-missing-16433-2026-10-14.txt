queryMissing currently reads derivations from the build store, even when the
evaluator placed them in another store. This causes misleading dry-run output
and can silently omit flake checks. Automatic Tarmac evaluation makes this
relevant. The explicit-existing-.drv wrapper and Tribuchet hook input-copy fix
address other code paths and do not supply this change.

Required paired adaptations before adoption
1. The virtual Store::queryMissing(targets) becomes queryMissing(targets,
Store *evalStore=nullptr). gRPC1136edc overrides the old one-argument form and
will not compile with this PR alone. Adapt declaration/implementation. For a
separate eval store, traverse client-side via Store::queryMissing(targets,
evalStore), as the PR does for RemoteStore. Use an API feature probe, not a
2.36 version check: both our old and new Nix identify as 2.36 prerelease.
https://github.com/Mic92/nix-grpc-store/blob/1136edcf65413ab721385ed599b11e79e291dacc/src/client/store.hh#L289
https://github.com/Mic92/nix-grpc-store/blob/1136edcf65413ab721385ed599b11e79e291dacc/src/client/transfer.cc#L64
2. flake.cc invokes store->getBuilder() without passing getEvalStore(). The
PR improves check selection but leaves this call unchanged. Store::getBuilder
explicitly defaults to the build store as evaluation store. Follow-on change
should be store->getBuilder(getEvalStore()) with a regression test. This is a
source-based inference, not an executed reproduction in this review.
https://github.com/NixOS/nix/blob/a9f38ea0ee89f550616f342386f45e896f4abd18/src/nix/flake.cc#L829
