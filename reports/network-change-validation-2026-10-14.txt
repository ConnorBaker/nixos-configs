SECONDARY / GENERIC ETHERNET FALLBACK
A later generic 15-ether.network can preserve DHCP on other physical interfaces:
  [Match]
  Kind=!*
  Type=ether

  [Link]
  RequiredForOnline=no

  [Network]
  DHCP=yes
  DNS=1.1.1.1
  DNS=2606:4700:4700::1111
  DNS=1.0.0.1
  DNS=2606:4700:4700::1001
  DNS=2a01:4f8:c2c:123f::1
  DNS=2a00:1098:2b::1
  DNSOverTLS=true
  DNSSEC=allow-downgrade

  [DHCPv4]
  RouteMetric=4096
  UseDNS=false

  [IPv6AcceptRA]
  RouteMetric=4096

4096 is deliberately higher than ALL normal primary RA preference metrics
512:1024:2048. A fallback RA metric of 2048 loses to the present primary metric
1024 but ties the primary's low-preference default 2048. Using 4096 avoids that
tie if router preference changes later. Primary static IPv4 default has metric 0.
DHCPv6 RouteMetric controls delegated-prefix subnet routes, not an ordinary IPv6
default gateway; RA RouteMetric must be configured to control the fallback
IPv6 default. There is no need to set DHCPv6 RouteMetric without PD intent.
Fallback networks must have no host static Address or Gateway and no IW route.
This produces backup connectivity; it does not make the unplugged second NIC
an independent live management path today.

WHY .NETWORK RELOAD IS THE APPROPRIATE APPLY PATH
Live systemd is 261.3 on both hosts. networkd Type=notify-reload, CanReload=yes.
Current daemon PID desktop 1898, ext 1535, active since approximately 02:00 UTC.
Pinned NixOS networkd module lines 4237–4251 makes .network files reloadTriggers;
.link/.netdev files and networkd.conf are restartTriggers. stopIfChanged=false.
A change restricted to .network files should reload, not stop/start networkd,
provided the systemd package/service definition and nonreloadable inputs do not
also change. The actual built-generation diff must verify that assumption.

Source-reviewed systemd 261.3 behavior:
* manager_reload() reloads .network files then reconfigures with flags=0.
* link_get_network() matches the immutable permanent hardware address separately
  from the current MAC and selects the first matching file in sorted order.
* link_drop_unmanaged_addresses() explicitly retains an existing static address
  when matching new static configuration can update it. Same 192.168.1.x/24 and
  prefix/peer/address settings preserve the management address.
* link_drop_routes() retains still-requested static routes and kernel routes;
  removing extra default-route policies leaves the existing plain Gateway route
  and connected /24 route. Do not delete ALL Gateway declarations temporarily.
* link_drop_dynamic_config() keeps DHCP lease state when enabled in both old/new
  profiles. DHCPv6 client objects are recreated, but leases are retained.
* NDisc routes remain if RA route-policy settings are unchanged. SLAAC addresses
  remain when autonomous prefix/tokens/filter settings are unchanged.
* With no [Link] MACAddress, link_request_to_set_mac() makes no MAC-set request;
  it does not trigger a primary hardware-address transition.

Do NOT run networkctl reconfigure unnecessarily after a successful reload.
The reconfigure API uses LINK_RECONFIGURE_UNCONDITIONALLY|LINK_RECONFIGURE_CLEANLY,
which can stop DHCP/NDisc engines and drop dynamic configuration. That differs
from a normal reload. Do not add KeepConfiguration=yes to conceal errors: it
alters cleanup behavior and is unnecessary for unchanged address/lease settings.
These source properties support continuity but are not a guarantee against
unrelated driver/hardware/service failures; use host-local automatic recovery.
