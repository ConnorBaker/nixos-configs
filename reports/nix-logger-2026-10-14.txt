Current optimized Nix input: a9f38ea0ee89f550616f342386f45e896f4abd18.
Reviewed commit: d3538dea35b77bcfddf6a79c74b4bb2cd44d2fee.
Repositories were not edited; no live builders or services were changed.

Recommendation
The change targets a relevant reliability problem in our remote build path,
but do not cherry-pick the literal commit. It was merged accidentally despite
failing CI and then reverted. A corrected backport could be useful after
fixing its locking, characterization test expectations, and validating the
actual remote upload path. It is not an evaluator optimization and does not
explain the existing HTTP cold-substitution timeout without matching evidence.

What it does
copyPaths reports progress for each NAR chunk. build-remote uses JSONLogger
on stderr, a pipe consumed by the daemon. A full pipe can block a hook inside
a copy while it holds the remote's shared upload lock, stalling other builds.
The patch samples non-final resProgress to at most one update per 100 ms per
activity. Completion updates with nonzero expected and done >= expected are
kept; non-progress results and build log lines are retained. This mitigates
a trigger, not the underlying possible blocking of a logging pipe.

Relevant source paths at our pin
src/nix/build-remote/build-remote.cc:76 installs JSONLogger.
src/nix/build-remote/build-remote.cc:290-324 holds uploadLock around copyPaths.
src/libstore/store-api.cc:1091-1103 emits progress from the per-chunk sink.
src/libstore/build/derivation-building-goal.cc:1226+ synchronously negotiates
another build hook, alongside event-loop consumption of accepted hooks.
Our gRPC remote builders use build-remote, so changing the transport alone
does not remove this local logging pipe. In addition, the gRPC plugin's
src/client/build.cc uploadDrvClosure has its own per-chunk progress sink.
Tribuchet's Rust attach process does not itself use Nix's JSONLogger, so the
patch does not make its raw log forwarding nonblocking. Tarmac evaluation
and PGO compilation do not fix the hook pipe problem.

CI diagnosis
Ubuntu jobs, including syscall-fallback run, passed both new JSONLogger
tests. Existing JSONLogMessageCharacterisationTest.writesExpectedLogs/1
(legitimate fixture) failed. macOS failed the same existing golden test.
That fixture replays many immediate progress updates and expects them all
to be re-emitted, conflicting with intentional rate limiting. Thus CI
failure is more specific than simply an untested build failure.

Additional source review finding (inference, not reproduced race)
The literal patch has:
  auto & last = _state.lock()->lastProgress[act];
  if (now - last < progressInterval) return;
  last = now;
Sync::lock returns an RAII guard; this temporary guard ends at the first
semicolon. The following reads/writes of last are outside the mutex. Two
progress calls can race, and stopActivity can erase that map entry while a
reference remains. A corrected patch must keep a named guard across map
lookup, comparison, and assignment, then release it before write(), which
also acquires _state. Move the rate-limit check before JSON construction
if aiming to reduce per-chunk JSON work as well as pipe writes. Test first,
final, unknown-size, independent activities, teardown, and concurrency;
make characterization coverage insensitive to intentionally dropped
intermediate progress rather than disabling the failing test.

Applicability
patch --dry-run -p1 against the actual Nix input succeeded for all three
files. Includes hunk used fuzz 1; other hunks only used line offsets.
Existing local patches do not overlap these logging/test files. That only
proves textual applicability, not correctness. It does not change public
Nix headers, store format, remote protocol, or certificate requirements.
All optimized/profiling variants must get the same corrected patch, and
PGO profiles must be regenerated through the normal source-dependent
derivations. Tarmac and gRPC must relink to those same rebuilt components.

Our package's current test gate
tarmac.nix wraps components.nix-cli and inherits nix-everything.libs as
passthru. Accessing libs does not build nix-everything. Upstream explicitly
documents nix-cli as lacking the unit/functional test gate and recommends
building nix-everything to exercise it. Existing flake checks only cover
format/lint. Tarmac package doCheck=true tests its core, not all Nix tests;
its tests/e2e.sh is separate from the Meson test list.
