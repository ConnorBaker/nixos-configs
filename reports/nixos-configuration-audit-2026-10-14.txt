NixOS configuration audit — 2026-10-14

Outcome
There are worthwhile simplifications, including concrete networking
misconfigurations and several workarounds superseded upstream. The largest
maintenance improvement is sharing the fleet policy and filesystem/secret
declarations. Performance settings need individual review; enabling bpftune
does not replace the entire networking module.

Five parallel read-only reviews examined the four declared configurations,
the locked Nixpkgs modules, relevant path histories from 2023-10-14 through
2026-10-14, upstream release notes, and selected live observations on desktop
and ext. This is a review of modules relevant to these machines, not an audit
of every Nixpkgs commit. Build01/Orin were inspected through source/evaluation
only. No offline-host builds, workload benchmarks, deployments, storage
changes, or zfs-dedup execution were performed by this audit.
Baseline: Nixpkgs 7fd4004d0511991fff3a0524856a9be09e28c5f0.

Recommended priorities

1. Correct physical-interface identity and simplify routes first.
   devices/nixos-desktop/hardware.nix:72; devices/nixos-ext/hardware.nix:37;
   corresponding build01 hardware block; modules/networking.nix:37,133.
   The broad physical-Ethernet match combines with linkConfig.MACAddress to
   SET the same MAC on every matched NIC, rather than select the intended
   interface. Runtime confirms duplicate MACs on both NICs of desktop and
   ext. Give the static LAN rule a specific stable match (e.g. permanent
   hardware MAC), and let other NICs use the general physical-interface rule.
   Retain an explicit MAC assignment only if spoofing is actually intended.

   Remove DHCP-server reservation declarations from these client-only
   configurations. Each host already has a static /24 with an on-link router;
   Gateway plus the extra on-link route and shared congestion-window route
   currently produce three default routes. Use one default route; document
   any desired route window settings on that route. Remove redundant router
   host routes. The 10Gbps desktop/ext path uses their connected /24 route,
   so current default-route window settings do not tune this peer traffic.
   Plan a network change with local console/recovery access and verify IPv4,
   IPv6, Tailscale, SSH and direct peer routes before relying on it remotely.
   See nixos-networking-audit-2026-10-14.txt for generated/runtime evidence.

   Also replace the option-type extension that applies uplink defaults to
   every systemd.network.networks entry. An evaluated Orin USB gadget server
   inherits DHCP=yes, public DNS, strict DoT and a _dhcp4 default route. Apply
   common defaults only to physical Ethernet/WLAN profiles and give the
   downstream USB network its own explicit DHCP-server policy.

2. Remove superseded workarounds and genuine redundant declarations.
   devices/nixos-desktop/hardware.nix:47-63: use only the enabled
   nix-required-mounts NVIDIA preset; its current implementation follows
   /run/opengl-driver symlinks. The manual tmpfiles-derived target is obsolete
   since February 2026. Local hook validation returned the same three mounts
   with and without that explicit target.
   https://github.com/NixOS/nixpkgs/commit/02b74722d86f55b367011ac4b9ebafe7ffcbb11c

   modules/docker.nix:8: CDI is enabled by Docker>=28.2.0 since May 2025.
   Remove the explicit features.cdi=true flag, keeping the NVIDIA toolkit.
   https://docs.docker.com/engine/release-notes/28/#2820

   modules/zfs.nix:40,54: Disko's fileSystems already imply ZFS/vfat support;
   root and /persist imply initrd ZFS. Evaluation without both explicit lists
   passes all assertions on all four hosts, preserves stage 2 filesystem
   support, and removes unneeded initrd FAT modules. Boot validation remains
   required before calling the changed initrd proven on hardware.

   Remove repeated SSH/exporter defaults, duplicated Git/htop package entries,
   old commented ext dpool rollback code, and redundant zstd declarations.
   These are mostly longstanding defaults, not new 2026 changes. Keep options
   that intentionally differ from defaults, including SSH password policy.

3. Consolidate common policy and data with ordinary NixOS modules.
   devices/*/default.nix: one common builder profile can replace the repeated
   import manifests; retain the Orin exporter exception explicitly.
   devices/*/disko.nix and util.nix: share the identical root-pool datasets and
   root@blank hook; keep disk serials, topology, mountpoints and properties.
   devices/*/secrets.nix: share identical SOPS/age setup, while each host sets
   its own local defaultSopsFile. Fix README's obsolete RSA/GPG requirement.
   modules/nix/default.nix:59-100: promote the existing lightweight machine
   inventory to a pure data file, feeding host addresses, architectures,
   build features, SSH keys and hub selection. Preserve external spark-ee4c.
   Do not evaluate other nixosConfigurations to discover these values.

   This eliminates repeated declarations without introducing a role framework
   or custom configuration language. Validate evaluated service flags, disk
   declarations, filesystem options, secret paths and build routes before/after.

4. Stop running an unused Prometheus server; retain the exporters.
   modules/services/prometheus-exporters.nix:4-5 enables a local server despite
   the module's documented external scraping. The desktop daemon is running
   with empty scrape_configs, remote_read, remote_write and rule_files. Exporter
   enable flags work independently. Remove server enable/reload declarations
   after checking for any undocumented consumers of its local 9090 endpoint.
   This is unused-service cleanup, not a changed upstream default.

5. Revisit memory-heavy tuning based on changed upstream behavior.
   modules/nix/default.nix:131: download-buffer-size=256MiB was motivated by an
   older shared-download-thread stall. Nix switched to curl pause in 2025 and
   reduced its default to 1MiB. Prefer the new default unless workload evidence
   justifies the override. At 32 connections the threshold totals can reach
   about 8GiB versus 32MiB; these are potential limits, not measured residency.
   https://github.com/NixOS/nix/commit/4307420c4473bed25eef8e27d1935f5af0658d03
   https://github.com/NixOS/nix/commit/a2d6a69d45d83cc44126b61b8926882cf63edcac

   Review nar-buffer-size=1GiB separately: this is a different import-buffer
   setting, still a custom value, and the download fix does not prove it can
   be removed. Measure peak memory and import throughput before choosing it.
   zram memoryPercent=400 is logical uncompressed capacity, not preallocated
   physical RAM or a physical-memory ceiling. It can still contribute to poor
   pressure behavior. High dirty ratios do not directly tune ZFS ARC/dirty-data
   accounting; coordinate changes with the earlier ZFS report and real builds.
   Initrd zstd-19 is also a genuine override; measure rebuild time versus -10.

6. Adopt maintained interfaces where they reduce local coupling.
   hardware.nvidia.branch="latest" and moduleParams.nvidia can replace the
   desktop's direct driver-package reference and raw modprobe string. These
   interfaces landed in 26.05; preserve the same branch and profiling policy.
   https://github.com/NixOS/nixpkgs/commit/c647c537e4eae57bfff3b85af69ae8e1a84568aa
   https://github.com/NixOS/nixpkgs/commit/dd7a6716584345d27753fe8529087938f86731af

   Orin's explicit CUDA support/capability values duplicate Jetpack's SOM-derived
   values. Its graphics.enable=true remains necessary. A global shared pkgs
   rewrite must account for Jetpack's injected overlays/configuration and
   desktop's CUDA variant. readOnlyPkgs can optionally share compatible base
   instances; measure evaluation savings before expanding the abstraction.

bpftune answer
It can manage netdev_max_backlog, tcp_max_syn_backlog, TCP buffer maxima, UDP
receive buffer defaults/maxima, and connection-specific congestion control.
Its TCP tuner leaves the minimum/default elements of tcp_rmem/tcp_wmem intact.
It does not manage all static TCP timeout, keepalive, UDP minimum, qdisc or
socket-limit settings in our module. Both live hosts have all nine tuners
active and full support; TCP maxima have grown far above our 16MiB boot values.
Static boot settings are initial values, not an automatic tuner disable.
Later administrative sysctl writes can disable related tuners until restart.
Remove tunable boot overrides selectively and do not repeatedly reapply those
sysctls while assuming bpftune retains ownership. Keep intentional fallback
congestion/qdisc policy separate from adaptive buffer tuning. The networking
appendix enumerates exact ownership, bounds, runtime data and source caveats.

Important retained policies and optional follow-ups
Keep the documented desktop 5.2GHz stability cap, microcode/firmware support,
explicit NVIDIA open-driver choice, Orin graphics/toolkit predicate, root
rollback ordering, /persist neededForBoot, native zfs-mount disabling, and
existing stateVersion values. Existing checksum/sync/txg choices are policies
already reviewed in zfs-and-package-audit-2026-10-14.txt. The user's broad
tailnet access policy stays outside this cleanup.

Optional migrations deserve separate changes: direnv shell integration,
Facter with actual target reports, systemd-boot boot counting with health/recovery
validation, and sharing more package instances. nil's dedicated input contains
a fix absent from packaged nil, and nix-direnv is substantially ahead of the
packaged release: neither input is identical boilerplate. histodu has no pinned
Nixpkgs equivalent. Merely removing those inputs would lose functionality.
