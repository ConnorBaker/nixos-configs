  This fixes a real system documentation build failure with unwritable HOME.

This is the full dependency change, not merely the Nix diff: Nix's scoped
libgit2 uses 2.0.0-rc.1 at ae45d0d168f7e8dbfdb8c623589cb51caac96ab3 plus the draft's
zlib-ng, memory-config-backend and packbuilder configuration patches. Global
pkgs.libgit2 is unchanged. The source port keeps upstream's existing parallel
writer pool, sets dontFindDeltas in shared options, and uses an in-memory
pack.window=0 override without changing the on-disk Git config.

Tradeoff: the draft disables Git-object rehash-on-read process-wide for the
Nix fetcher, reducing detection of corrupt cached Git objects. Newly created
objects are hashed and expected NAR hashes/signature checks remain. An isolated
wrong-narHash fetch was rejected. Do not describe this as unchanged corruption
checking or claim a measured build-workload speedup.

The optimized system CLI, daemon, Tarmac and gRPC plugins and nix-eval-jobs all
use the same patched Nix component scope. The gRPC PR204 drain/upload/scheduling
patch previously authorized remains included and was rebuilt for the new scope.
