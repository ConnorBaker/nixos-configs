Tarmac duplicate-registration fix — 2026-10-14

User failure
nixos-rebuild switch --flake . --sudo failed in its bootstrap nix build with:
  error: Already registered store with name 'Tarmac Store'
The user's terminal predated the last switch. This exact error was reproduced
by passing the preceding generation's Tarmac loader in inherited NIX_CONFIG
while invoking the current Nix wrapper. A clean environment did not reproduce
it. The original integration tests missed cross-generation inherited state.

Cause
The wrapper appended its own extra-plugin-files setting without removing an
older Tarmac entry. makeWrapper only deduplicates identical configuration text;
old and new store paths differ. Nix loads both loader DSOs. Each loader dlopens
its own native plugin, whose static registration tries to register the same
store name. Nix's duplicate-registration check correctly rejects that state.
This was a defect in our wrapper, not a missing upstream Nix patch.

Fix
Published nix-optimization branch nixos-nix-tarmac at
b8d76e7e0e735fba57df8f0e6d9c58208da4cf4f. Updated the root flake through ordinary
nix flake update nix-optimization. Root source change commit 1bc0969.

A shared tarmac-wrapper-init.nix handles the CLI and embedded nix-eval-jobs.
Before either Nix binary initializes plugins, it removes inherited Tarmac
loader/native entries from NIX_CONFIG's plugin-files/extra-plugin-files lists,
then appends exactly one loader for its selected component scope. It handles
plugin directories and mixed directories while preserving their other plugins,
including gRPC. It retains other settings, assignment/append semantics and
comments. Stale standard Tarmac plugin directories can also be discarded after
GC. It does not execute configuration text or change HOME. Existing sandbox
cache selection and CLI evaluation-store override behavior are retained.

This scopes automatic wrapper configuration. Independently configured plugin
paths in nix.conf, included files or explicit command-line plugin overrides
remain the caller's settings; the fix does not silently rewrite those files.
It deliberately selects the managed ABI-matched Tarmac instead of exporting
NIX_TARMAC_PLUGIN_OVERRIDE, which could force a foreign ABI into child Nix.

Regression validation
checks.x86_64-linux.tarmac-inherited-plugins invokes the versioned
nix-optimization/tests/tarmac-inheritance.sh. It copies a real plugin to a
separate generation-like location (distinct native DSO), then tests eleven
configurations with both CLI and embedded evaluation: loader/native files,
loader/native directories, mixed gRPC directories, whitespace/comments,
repeated entries, later base-list assignments and collected-directory paths.
It verifies one selected Tarmac entry, retained gRPC and other settings, and
successful evaluation. A nested nix shell invocation also passes. The store,
config and cache are private, and no host build delegation occurs.

Also passed: sandbox-cache regression, 33 Tarmac-wrapped nix-eval-jobs
functional tests, pre-commit checks, and complete desktop/ext system builds.
