Overlay and nix-eval-jobs integration — 2026-10-14

Package construction
Optimized Nix, histodu and Tribuchet no longer come from foreign flake packages
attributes. gRPC no longer uses a separate infrastructure Nixpkgs import.
All construct through the caller's final package set. nix-optimization inputs
Nix and Nixpkgs follow our root inputs. Its new published overlay API accepts
caller pkgs; the public variant factory still supports standalone system use.
Published nixos-nix-tarmac branch commits:
82e64b0: consumer-pkgs overlay API and reusable Tarmac wrapper factory.
95c1a7f: preserve upstream unit-test executable names when naming PGO variants.
https://github.com/ConnorBaker/nix-optimization/tree/nixos-nix-tarmac

The upstream unit runners use pname to find executables, while Meson installs
unsuffixed names. Existing optimization suffixes broke those runners. Test
components now keep pname and vary their derivation name, without changing
the runtime libraries. Root flake exposes actual optimized component tests.

Main is 9f1553af (v2.35.4), included as a non-flake source input. John Ericson's

The package links our exact optimized Nix components and Boost 1.89, and enables
upstream unit tests. It embeds Nix evaluation rather than invoking the CLI,
so using a wrapped nix executable alone cannot select Tarmac for its workers.
Its own wrapper loads the same Tarmac plugin, defaults --eval-store tarmac://,
and exposes nix=pkgs.nix (wrapped system CLI). Explicit --eval-store arguments
override the default. This also gives consumers such as nix-fast-build the
wrapped Nix via passthru. gRPC and Tarmac plugin libraries use the same ABI.
